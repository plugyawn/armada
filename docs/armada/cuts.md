# What is cut, hidden and kept

Reduced from the design folder's cut list (third final, 14 October 2026): every
Zulip feature and destination, and every piece of the proof of concept's own
chrome, with one verdict each. The last column names the work package of the
build plan that carries the line out. The full list, with the files each cut
touches, is `var/armada-overhaul/design/final3/CUTS.md` on the rebuild's
machine. A line marked **(P-n)** follows a decision the user has not made yet.

**The list is approved.** On 14 October 2026 the user said "cut useless
things" (`var/armada-overhaul/BRIEF.md`, statement 21): every line is carried
out as written, by the package in its last column, by deleting the code. The
two lines kept after review stay kept: code keeps its syntax colours (K-71
cuts only Zulip's stylesheet for them) and reactions keep a small emoji picker
(K-137). One line is still conditional: S-10 (`corporate/`) says "only if
approved", and the approval did not name it, so ask the user before carrying
it out.

This file is maintained by hand, from `var/armada-overhaul/design/final3/CUTS.md`
(the design folder's list; last changed on 15 October 2026, when K-37, K-77,
K-93, K-95 and K-96 were corrected from the reports of F2b and F5,
`var/armada-overhaul/build/STAGE-NOTES.md`) and the user's brief
(`var/armada-overhaul/BRIEF.md`, through statement 21); neither is
in the repository and no script writes this file. A change to the list is
made in this file as well, by whoever makes it, and this file is what the
code is held to.

- **CUT**: the code is deleted, with its templates, styles, hotkeys, event types and tests. Where a server feature sits behind it, the endpoints stay in place and unreachable until the server lane removes them (S-15).
- **HIDE**: it keeps working and has no standing place on screen. It is reached from the palette (⌘K) or one menu.
- **KEEP**: it stays and is redrawn in the design language.

**A line changes only when the user says so, by its id.** Each CUT or HIDE line is one change inside the package in its last column (`PLAN.md`); nothing else depends on it unless the line says so. Sizes are from `maps/lean-weight.md` (minified script unless said); "importers" are other modules that must be edited.

Counts, by id: in the client 85 CUT, 8 HIDE and 40 KEEP; on the server 10 CUT, 4 HIDE and 1 kept and moved.

## Never cut: what Armada's own semantics rely on

A change that touches one of these is a bug, whatever line it claims to implement.

- **`submessage.ts` and the `submessage` event.** Artifacts and live runs ride on them after polls and to-dos are gone.
- **Embedded bots, bot accounts and API keys.** Onyx is an embedded bot service; its admin block, runtime sign-in and keys live in that machinery.
- **Topic rename, move and resolve.** They re-key the worktree and its monitors by name (`zerver/lib/pear_worker.py`).
- **Channel creation with a Git repository.** It is the only way a repository is attached today; it becomes the Repository dialog.
- **Per-message read flags, the list model (`message_list.ts`, `message_list_data.ts`), `/near/` links and the 16 search operators.** The view is replaced; these are not.
- **Typing and presence events.** The agent's "working" signal to other clients is a topic typing notification.
- **User-group data.** Mentions and permissions read it after its overlay is gone.
- **Linkifier rendering on the server; image previews; Markdown parity between client and server** (the split of a message into bubbles and blocks depends on it).
- **`populate_db`, `pear_demo_data`, `rundjangoserver`** in `zilencer/management/commands/`, until S-09 moves them.
- **The `desktop-login` entry and `electron_bridge.ts`**, for the Electron shell.
- **The artifact contract** (`pear_artifact_contract_generated.ts`, `zerver/lib/pear_artifact_contract.py`): generated elsewhere, never edited by hand.
- **Every `$t` call site.** English ships alone; the tagging stays.
- **The classes the server puts on highlighted code**, and the emoji names data: the four syntax roles and the small picker are drawn from them, and so is `:` completion.
- **Monitors' models, events and endpoints** (`PearMonitor`): the Runs list reads them.
- **The search operators `has:link` and `has:attachment`, channel subscriptions as the client holds them, and a person's time zone**: the column's Shared, Together and People lists are drawn from them (P-8).
- **The behaviours F0 pinned** (`PLAN.md`, Appendix B). A cut may remove a key or a layer that belonged to a cut feature; it may not change a pinned row, and it says in its report which keys it removed.
- **The server's `pear` namespace**: models, routes, settings, events. Its rename is a separate step.
